# mh TypeScript 移轉｜語法轉換器原型階段結案紀錄

## 一、結案目的與狀態

**狀態：原型階段結案。**

本紀錄正式整理語法轉換器原型階段的目標、已完成的工作、最後一次已回報的驗證結果，以及這些結果不能支持哪些更廣泛的結論。

原型專案位於 `Z:\share\ts-mh-prototype`。本階段的目標是驗證：能否利用 TypeScript AST 與語意資訊，將本專案實際使用的部分模組化 TypeScript 輸出轉換為符合既有 `mh` 全域命名空間形式的 JavaScript。這不是建立通用 TypeScript 轉換器的承諾。

## 二、完成的工作

### 2.1 模組與類別轉換

原型已實作並以測試案例驗證以下行為：

- 使用 TypeScript AST 與語意資訊辨識模組匯入、匯出及符號引用。
- 將符合原型支援範圍的匯出類別轉換為 `mh.<path>.ClassName = class ClassName {}` 形式。
- 解析 named import、import alias 及其對應類別，將相關引用轉換為相應的 `mh` 命名空間路徑。
- 移除原始 import 宣告。
- 區分真正的匯入符號引用與同名的區域宣告，避免把函式參數、巢狀 callback、解構參數、catch 參數、迴圈變數等 shadowing 情境誤轉換。
- 處理 object shorthand property 與一般 object property 的 value 引用，保留 property key，並轉換其 value。
- 以回歸測試及輸出快照測試保護已涵蓋的行為。

### 2.2 手動診斷腳本與正式測試分離

三個原本命名為 `test-*.mjs` 的手動診斷腳本已改名為：

- `diagnose-compiled-symbol.mjs`
- `diagnose-shorthand-symbol.mjs`
- `diagnose-symbol.mjs`

這些腳本用於手動研究／排查 TypeScript Compiler API 的 symbol、declaration 或 shorthand property 行為，不是正式自動化測試。改名是為了避免 Node.js 的 `node --test` 自動探索並執行它們；改名時沒有改變腳本內容，舊檔名也已移除。需要時可直接以 `node .\diagnose-compiled-symbol.mjs` 等方式執行。

## 五、不能據此認定的事項

本階段結案**不代表**：

- 轉換器支援所有合法 TypeScript 或 JavaScript 語法。
- 所有可能的 import/export 形式、類別型態、模組解析情境或作用域情境都已涵蓋。
- 原型已通過主線全部原始碼的轉換。
- 主線 `Z:\share` 的型別檢查、建置流程或命名空間映射已完成。
- 產出已整合至正式 `my-mh-aid.js`。
- 產出已在 MouseHunt／Tampermonkey 實際執行環境完成端到端測試。
- 轉換器已通用化，或其效能已經最佳化。
- 早期曾出現的 Windows `EPERM` 輸出檔刪除異常已找到根因或永久修復。

自動化測試與型別檢查只支持其實際涵蓋的輸入、設定與檢查範圍；不可將局部驗證擴張解讀為整體移轉完成。

## 六、後續處理決策

- 原型階段在此正式結案；原型保留為研究與測試工具。
- 後續不再以擴充或通用化轉換器作為主線移轉的前置條件。
- 回到主線 `Z:\share`，先核對 `ts-src` 實際檔案與依賴，再重新執行主線型別檢查。
