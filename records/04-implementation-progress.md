- 根目錄具有 `tsconfig.json`。

以上項目不代表目前所有檔案均已再次核對，也不代表完整轉換流程已經完成。

## 三、目前進度的認定原則

後續整理進度時，必須分別記錄以下狀態：

- **已實作**：相關程式碼或設定確實存在。
- **已通過編譯檢查**：有實際執行結果支持。
- **已通過整合測試**：產出已整合至既有腳本，並完成相關測試。
- **尚待驗證**：已有實作或設計，但缺乏足夠證據確認結果。
- **尚未實作**：尚未完成相關工作。

單純存在程式碼，不代表功能已通過驗證；單純通過 TypeScript 編譯，也不代表產出的 JavaScript 在 MouseHunt 環境中能正常運作。

## 四、後續工作優先順序

後續應先核對目前實際進度，再依驗證結果選定下一個里程碑，不預先假定所有工作都已完成。

優先確認以下事項：

1. 目前 TypeScript 原始碼及目錄結構是否符合既定架構。
2. 現有程式碼是否能通過專案型別檢查。
3. TypeScript 模組如何轉換成符合既有 `mh` 全域架構的 JavaScript。
4. 類別與常數的輸出規則是否一致，且不會造成命名空間衝突。
5. 轉換後的程式碼是否能整合進 `my-mh-aid.js`。
6. 整合後的功能是否經過實際執行測試。

每次只選定目前最需要解決的具體問題，不應在缺乏驗證證據時，同時宣稱整條移轉流程已完成。

## 五、下一個里程碑的建立方式

下一個里程碑應在核對實際狀態後正式命名，並至少包含：

- 里程碑名稱及目標。
- 開始時的已知狀態。
- 本階段預計完成的具體工作。
- 驗收條件。
- 實際測試方式。
- 完成證據。
- 尚未解決的問題。
- 下一階段的進入條件。

若工作只完成部分內容，應記錄為部分完成，不應為了維持里程碑形式而將未完成項目視為成功。
